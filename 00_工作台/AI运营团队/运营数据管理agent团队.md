# 运营数据管理 agent 团队

更新时间：2026-07-24  
维护者：助理（AI 总协调 agent）  
状态：已建立 v0.1，等待首轮真实任务校准

## 团队使命

运营数据管理 agent 团队只负责艾维美术馆运营数据管理系统的开发、维护、测试、发布和技术可靠性。它提供系统与数据基础，不替代馆长、财务或运营负责人做经营决策、记账、退款、付款、报价或对外承诺。

## 团队结构

| 角色 | 职责 | 固定交付 | 使用的 skill |
|---|---|---|---|
| 需求与技术负责人 | 把业务目标转成系统范围、技术方案、版本计划和风险清单 | 需求卡、技术方案、迭代清单、发布说明 | `aiwei-operations-system-delivery` |
| 开发维护 agent | 实现功能、修复缺陷、维护数据模型和系统代码 | 代码变更、迁移、开发记录、复盘 | `aiwei-operations-system-delivery` |
| 测试与发布保障 agent | 验证核心流程、检查部署证据、发布纪律、回滚准备 | 验收清单、测试结果、发布记录、风险报告 | `aiwei-operations-system-delivery` |
| 治理与风控 agent | 检查权限、备份、数据口径、敏感信息和生产变更风险 | 治理评分卡、整改任务、验收标准 | `aiwei-operations-system-governance` |

## 当前事实

- 系统已上线腾讯云 Docker 架构，前端为纯 HTML/CSS/JS，后端为 Node.js REST API，数据库为 PostgreSQL 17。
- 7 月已完成项目清单、空间收款、画廊销售、图表统计、用户修复等多轮迭代。
- 当前 P0 治理风险包括：API 鉴权、HTTPS、自动备份、退款/作废、库存扣减、采购入库、日结报表。
- 2026-07-21 日志显示：新建账户无法登录问题已修复，但 admin 服务端鉴权缺失仍是真实安全洞。

## 首批任务卡

### RV-TECH-001 API 鉴权与角色权限加固

- 优先级：P0
- 状态：待启动
- 服务目标：防止未授权请求直接创建用户、修改数据或读取经营数据。
- 执行单元：运营数据管理 agent 团队 / 治理与风控 agent + 开发维护 agent
- 截止日期：2026-08-07

#### 范围

- 要做：梳理当前登录、用户、写入接口的鉴权缺口；设计 session/JWT 或同等机制；区分 admin/editor/viewer 的读写边界；补充测试。
- 不做：不改真实用户密码；不删除历史用户；不在文档中暴露密钥。

#### 交付物与验收标准

| 交付物 | 完成定义 | 证据位置 |
|---|---|---|
| 鉴权方案 | 写明接口范围、角色边界、兼容策略和回滚方式 | 技术方案或开发日志 |
| 代码变更 | 未授权请求不能读写受保护数据 | 代码 diff 与 API 测试 |
| 测试记录 | admin/editor/viewer/未登录四类场景均测试 | 发布记录 |

#### 需要馆长决定

- 是否允许本任务进入生产部署。
- 是否保留现有账号体系，还是趁机要求全员重置密码。

### RV-TECH-002 备份与恢复演练

- 优先级：P0
- 状态：待启动
- 服务目标：确保经营数据可恢复，避免单点数据丢失。
- 执行单元：运营数据管理 agent 团队 / 治理与风控 agent + 测试与发布保障 agent
- 截止日期：2026-08-07

#### 范围

- 要做：设计每日备份策略、留存周期、备份位置、恢复演练流程和验证记录。
- 不做：不公开备份文件；不把数据库密码写入仓库；不替代财务对账。

#### 交付物与验收标准

| 交付物 | 完成定义 | 证据位置 |
|---|---|---|
| 备份方案 | 包含频率、留存、失败告警、恢复步骤 | 治理文档 |
| 恢复演练记录 | 至少完成一次恢复验证并留档 | 发布/运维记录 |
| 风险清单 | 标出仍需人工确认的成本、权限和存储问题 | 总协调工作盘 |

### RV-TECH-003 退款/作废、库存扣减、采购入库、日结报表

- 优先级：P0
- 状态：待启动
- 服务目标：补齐真实经营所需的财务闭环和库存闭环。
- 执行单元：运营数据管理 agent 团队 / 需求与技术负责人 + 开发维护 agent + 测试与发布保障 agent
- 截止日期：2026-08-21

#### 范围

- 要做：拆分四个功能的业务口径、数据表、操作日志、权限、前端流程和验收场景。
- 不做：不直接执行退款；不修改历史收入口径；不替馆长决定审批规则。

#### 交付物与验收标准

| 交付物 | 完成定义 | 证据位置 |
|---|---|---|
| 业务需求卡 | 每个功能有原单、状态、操作人、原因、时间等字段规则 | 需求文档 |
| 迭代计划 | 拆为可发布的小版本并标明依赖 | 开发计划 |
| 验收场景 | 正常、异常、回滚、权限四类场景齐全 | 测试记录 |

## 分派协议

总协调向本团队分派任务时，必须给出业务目标、范围、不做事项、事实源、交付物、验收标准、截止日和红线权限。本团队回报时必须给出完成内容、证据位置、未确认信息、风险、下一步和需要馆长决定的事项。
