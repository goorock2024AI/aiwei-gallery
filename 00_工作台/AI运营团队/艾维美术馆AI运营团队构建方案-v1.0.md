# 艾维美术馆 AI 运营团队构建方案 v1.0

更新时间：2026-07-21  
方案定位：以美术馆真实运营职能为组织基础，由总协调 agent 逐步建设和管理的成长型 AI 团队。

## 一、组织目标

这不是一组一次性配置完成的“AI 岗位”，而是一套会随美术馆业务发展而扩展的运营能力。现阶段的目标是：让馆长拥有一个能管理任务、调度专业能力、检查交付、形成经营节奏的 AI 总协调 agent；再围绕已经存在的长期专业工作，建立必要的专项 agent 或 agent 团队。

AI 团队服务于五类持续工作：

1. 内容与观众服务：线上内容、社群/私域、活动报名与现场观众体验。
2. 策展与展务管理：研究支持、策展判断、艺术家/主题/机构发现，以及展览的计划和执行管理。
3. 推广与商务合作：场地租赁、展览赞助、品牌联名、旅行渠道与企业团建活动策划。
4. 运营数据管理：只负责运营数据管理系统的开发、维护、测试、发布和技术可靠性。
5. 跨领域营收体系：由上述单元共同交付，而不是另设一个脱离业务的“营收 agent”。

## 二、基本组织原则

### 1. 人是决策与现实执行主体

馆长代表实际运营团队，保留项目立项、预算、报价、合同、付款、对外发布、合作承诺和现场处置的最终权力。AI 负责准备判断、管理过程和生产草稿；任何红线事项均需馆长明确确认后再执行。

### 2. 总协调不替代专业团队

总协调 agent 是“馆长办公室 + 项目办公室”。它不应亲自承担代码开发、专业策展研究、合作方案生产或内容日常生产，而应把任务交给合适的专业单元，并依据事先定义的标准检查其完成情况。

### 3. 角色不等于持续运行的实例

团队中的“agent”是稳定职责和工作上下文，不代表同时开着许多对话窗口。正常模式下只有总协调 agent 作为你的统一入口；它按任务调用专业 agent。只有需要并行研究、交叉核验或连续专业维护时，才启用一个小型 agent 团队。

### 4. 从工作证明能力，而不是预先堆能力

一项工作只有同时满足“长期存在、每月反复发生、存在独立专业判断、可定义交付验收”时，才值得形成专项 agent 或团队。否则以临时任务或 skill 处理。

## 三、三种能力单元的边界

| 形态 | 适用情形 | 包含内容 | 例子 |
|---|---|---|---|
| Skill | 方法稳定、输入输出明确、可重复调用 | 工作步骤、规则、模板、参考资料、必要脚本 | 会议纪要、场租报价框架、内容排期、展览倒排、日报核查 |
| 专项 agent | 需要领域判断和持续上下文，但子任务尚不多 | 领域资料、判断规则、工作台与固定输出 | 内容与观众服务、项目协调 |
| Agent 团队 | 有多个相互独立的子工作流，需要分工和交叉验收 | 团队负责人、专业执行角色、质量/复核角色 | 运营数据管理、策展与展务、推广与商务合作 |

## 四、v1.0 团队结构

```text
馆长 / 实际运营团队（最终决定、外部沟通与授权）
                    |
          AI 总协调 agent（唯一入口）
  ┌─────────────────┼──────────────────┬─────────────────┐
  |                 |                  |                 |
运营数据管理团队  策展与展务团队   推广与商务合作团队  内容与观众服务 agent
  |                 |                  |                 |
系统开发与维护    研究/策展支持      推广策划           内容与观众服务工作包
测试与发布保障    展览制作/执行      合作/场租推进
```

营收体系由总协调 agent 发起每周经营检查，由内容与观众、策展与展务、推广与商务共同承担业务结果；运营数据管理团队只提供系统与数据基础，不负责业务经营决策。

## 五、各单元的当前建设形态

### A. AI 总协调 agent（立即建设，核心单元）

**定位：** 馆长的运营助理、AI 团队负责人、项目办公室主任。

**主要职责：**

1. 维护一张总工作盘：目标、项目、任务、负责人、截止日、状态、阻塞、决策事项和证据链接。
2. 将馆长的目标拆成可执行任务包，选择交给哪个专业单元，并写明验收标准。
3. 接收专业 agent 的结果，核验是否满足任务要求；不满足则退回补充或上报馆长决策。
4. 每周形成项目推进与经营总结；每月形成复盘、收入结构、问题与下月优先级。
5. 发现能力缺口：提出新 skill、专项 agent 或团队的建设建议，但不自行扩编。
6. 维护 AI 团队能力目录：谁负责什么、用哪些资料、能读写什么、交付标准是什么、最近表现如何。

**不承担：** 代替馆长承诺合作/价格/预算；代替专业团队写生产代码或作出艺术专业最终判断；未经授权向外部发送信息、发布内容、修改生产数据或上线系统。

**固定节奏：**

| 节奏 | 总协调 agent 的交付 |
|---|---|
| 每日或有动态时 | 工作盘更新、待确认事项、下一步提醒 |
| 每周 | 项目进度、经营摘要、合作漏斗、内容进展、下周优先级 |
| 每月 | 经营复盘、项目复盘、营收结构、团队能力缺口与扩建建议 |
| 每次关键项目决策前 | 背景事实、备选方案、影响、建议与待确认项 |

### B. 运营数据管理专业团队（立即建设，独立技术团队）

**唯一使命：** 开发和维护运营数据管理系统。它不承担经营报表解读、业务定价、内容制作或合作跟进。

| 团队角色 | 职责 | 主要交付 |
|---|---|---|
| 技术负责人 / 需求分析 agent | 将总协调提交的业务需求转为范围、方案、风险和版本计划 | 需求澄清、技术方案、迭代清单、发布说明 |
| 开发维护 agent | 实现功能、修复缺陷、维护数据模型和系统代码 | 代码变更、迁移、问题修复、开发记录 |
| 测试与发布保障 agent | 验证核心流程、检查数据安全/备份/权限、维护发布与回滚纪律 | 验收清单、测试结果、发布记录、风险报告 |

**总协调如何验收：** 每个需求必须有业务目标、范围、验收场景、上线风险和版本记录；技术团队提交测试证据后，总协调只负责业务验收是否完成，不越权判断代码细节。

**必须首先沉淀的 skill：**

- `aiwei-operations-system-delivery`：需求受理、开发、测试、发布和回滚流程。
- `aiwei-operations-system-governance`：权限、备份、数据口径、生产变更和故障处理规则。

### C. 策展与展务管理团队（立即按项目团队方式启动）

**定位：** 既支持馆长的策展判断，也将确定的策展方向落为可执行展览。

| 团队角色 | 职责 | 主要交付 |
|---|---|---|
| 策展研究与资源发现 agent | 研究展览主题、艺术家、机构、作品线索和合作可能；提供比较与出处 | 研究简报、候选清单、策展论证、资源地图 |
| 展务计划与执行 agent | 把策展方向拆为作品、预算、合同节点、制作、布展、活动、现场、撤展和复盘 | 展览立项、倒排表、风险表、SOP、展后复盘 |

**现阶段优先项目：** 云南重彩画展。该项目应成为团队的第一套实战工作流，不因单个项目结束而消失；结束后将研究、立项、布展、活动、复盘中稳定有效的内容沉淀为 skill。

**第一批 skill：**

- `aiwei-curatorial-research`：艺术家、主题、机构与展览案例研究的来源要求、比对方法和输出格式。
- `aiwei-exhibition-delivery`：立项、预算、作品、供应商、布展、接待、撤展和复盘工作包。

**边界：** AI 可以主动发现和推荐，但艺术判断、作品真伪、借展授权、保险、安全与合同仍由馆长和实际专业人员最终确认。

### D. 推广与商务合作团队（立即按双工作流启动）

**定位：** 让美术馆的项目被看见，并形成可追踪的合作与收入机会。

| 团队角色 | 职责 | 主要交付 |
|---|---|---|
| 推广策划 agent | 为展览、活动、场地与合作项目设计受众、渠道、传播节奏、素材需求和效果复盘 | 推广计划、渠道矩阵、传播日历、投放/渠道复盘 |
| 商务合作与场租 agent | 研究与筛选合作方，维护赞助、联名、旅行渠道、企业团建、场地租赁的线索和推进资料 | 合作漏斗、客户画像、提案草稿、报价框架、跟进清单、权益表 |

**第一批 skill：**

- `aiwei-partnership-development`：合作方筛选、调研、提案、权益、跟进与复盘。
- `aiwei-venue-commercialization`：场地产品、档期、报价、看场、合同前资料与回款跟踪。
- `aiwei-promotion-planning`：推广目标、渠道策略、素材任务、活动推广和复盘。

**边界：** 团队可以准备清单、提案、邮件/私信草稿和报价建议，但不得代表美术馆发送、报价、承诺权益、签约或接收付款。

### E. 内容与观众服务 agent（立即建设为单 agent，以 skill 增长）

**定位：** 将美术馆的展览、活动和日常体验转化为持续内容与更好的观众关系。

**工作范围：** 线上内容、社群/私域、活动报名、现场观众体验；不额外承担本阶段未定义的人事、收藏管理或行政事务。

**固定交付：**

- 内容选题池、周/月内容日历、各平台草稿与素材需求单。
- 活动报名页信息、报名跟进清单、到场提醒和活动后反馈整理。
- 社群/私域互动建议、常见问题回复草稿、观众反馈与现场体验问题清单。
- 内容与活动效果复盘：触达、报名、到场、转化、反馈与下一轮优化。

**为什么先是单 agent：** 目前需要先验证内容与观众数据如何记录、哪些平台最重要、馆长的审核与发布节奏如何运作。此阶段的核心不是并行生产量，而是建立正确的内容-报名-到馆-反馈闭环。

**先沉淀的 skill：**

- `aiwei-content-calendar`：选题、排期、草稿、审核、发布记录与复盘。
- `aiwei-audience-service`：报名、到场提醒、现场体验、社群互动、反馈归档与问题升级。

## 六、营收体系的协同机制

营收体系不是独立团队，而是一张由总协调 agent 维护的“经营结果账”。

| 收入或经营结果 | 主要责任单元 | 协作单元 |
|---|---|---|
| 展览票务、活动报名、观众复访 | 内容与观众服务 | 策展与展务、推广策划、运营数据管理 |
| 场地租赁、企业团建 | 商务合作与场租 | 推广策划、内容与观众服务、运营数据管理 |
| 展览赞助、品牌联名、旅行渠道 | 商务合作与场租 | 推广策划、策展研究、内容与观众服务 |
| 收入记录、核销、库存、应收、日结 | 实际运营团队与经营机制 | 运营数据管理仅负责系统功能和可靠性 |

总协调 agent 每周把这些结果合并为经营简报：本周收入、潜在回款、客流/报名、合作线索、项目风险和需要馆长决定的事项。

## 七、总协调的分派与验收协议

每次向专项单元分派工作，必须有一张任务卡：

| 字段 | 要求 |
|---|---|
| 任务目的 | 说明它服务哪个项目或经营目标 |
| 范围与不做什么 | 避免专项 agent 无限扩展任务 |
| 输入与事实源 | 给出文档、数据、已有结论及确认状态 |
| 交付物 | 明确需要方案、清单、草稿、代码、报告或风险判断 |
| 验收标准 | 可检查的完成定义，不以“做得不错”作为标准 |
| 截止时间 | 包含需要馆长确认的时间点 |
| 决策权限 | 标为绿/黄/红，明确是否必须人工确认 |

专项单元回报时，必须提供：完成内容、证据位置、未确认信息、风险、下一步和需要馆长/总协调决定的事项。总协调 agent 依据任务卡验收，不凭主观印象宣布完成。

## 八、团队演化规则

### 1. 新建 skill 的触发条件

同类工作在一个月内出现至少三次，且流程、模板或校验规则已相对稳定，即由总协调提出 skill 建议，说明触发语、参考资料、输出格式、权限与维护人；经馆长确认后建立。

### 2. 新建专项 agent 的触发条件

某一领域需要连续上下文、独立判断和固定交付，且总协调每周至少两次需要调用该领域能力时，建立专项 agent。初期只配置一个负责角色，避免人为制造部门。

### 3. 升级为 agent 团队的触发条件

满足以下三项中的至少两项时，由馆长决定是否升级：

- 同时存在两个以上不可串行的子工作流。
- 工作质量需要独立复核，不能由同一 agent 自评。
- 连续六周存在稳定任务量，并且失误会影响收入、品牌、现场安全或生产系统。

### 4. 各单元的预期升级信号

| 单元 | 可能的升级信号 | 升级方向 |
|---|---|---|
| 内容与观众服务 | 多平台稳定高频发布；社群/报名/现场反馈同时成为持续任务 | 拆分为内容编辑 agent 与观众运营 agent |
| 策展与展务 | 同时推进两场以上展览，或艺术家/作品资源库持续增长 | 增加艺术家/机构研究 agent 或现场制作复核 agent |
| 推广与商务合作 | 有持续合作漏斗、场租客户和渠道项目并行 | 拆分为市场增长 agent 与商务发展 agent，并设合作资料复核 |
| 运营数据管理 | 频繁发布、多模块并行、线上故障或安全要求提升 | 增加数据迁移/可靠性 agent 或独立业务验收 agent |

## 九、建设顺序

| 阶段 | 建设重点 | 可验证成果 |
|---|---|---|
| 阶段0：定责 | 定义总协调工作盘、任务卡、验收协议、团队能力目录 | 总协调可对任何任务完成分派、追踪和验收 |
| 阶段1：技术稳定 | 建立运营数据管理团队的需求-开发-测试-发布工作流 | 版本、测试、发布、备份和问题反馈均可追溯 |
| 阶段2：服务核心经营项目 | 启动策展展务团队与推广商务团队，首先服务云南重彩画展和场地租赁 | 重彩展与场租均有可追踪任务、合作与风险台账 |
| 阶段3：建立观众闭环 | 启用内容与观众服务 agent，连接内容、报名、到馆、反馈 | 有稳定内容节奏和可复盘的观众数据 |
| 阶段4：按证据扩编 | 由总协调依据任务量、质量与风险提出新增 skill/agent 建议 | 每次扩建都有明确问题、验收目标与维护责任 |

阶段不是一次性项目进度表。总协调应根据实际工作动态调整顺序：例如重彩画展时间紧急时，可优先建立相关展务与推广工作包；运营系统出现关键风险时，技术稳定优先。

## 十、权限与安全底线

- 默认只读：专业 agent 可以分析资料、生成草稿、提出修改建议；写入项目台账、文档或代码应遵循明确授权。
- 双确认：报价、合同、付款、退款、对外发送/发布、生产部署、删除数据、修改权限必须由馆长或授权人确认。
- 可追溯：任何正式交付应保留来源、版本、确认状态和负责人；技术变更还应保留测试与发布记录。
- 事实优先：项目状态、经营数据、展览档期、合作信息发生冲突时，先标记冲突、请求核验，不得编造确定结论。
- 外部沟通：在当前工具限制下，AI 只准备沟通材料与跟进清单，由馆长完成现实世界的发送、约见和确认，再将反馈回填给总协调。

## 十一、v1.0 的完成定义

这份方案落地的标志不是创建了多少 agent，而是：

1. 馆长只需面对总协调 agent，即可获得当前工作全景、下一步和待决策事项。
2. 每项工作都能被分派给明确的专项单元，并有可检查的完成定义。
3. 运营数据管理系统的技术工作与经营分析工作明确分离。
4. 重彩画展、场地租赁、营收体系三条主线能被四个专业单元协同推进。
5. 内容与观众服务先形成闭环，再依据真实任务量决定是否扩为团队。
6. 每次新增 skill、agent 或团队都有真实需求、明确边界和馆长确认，不为“组织完整”而扩张。
