编制日期：2026-07-25  
状态：RV-P0-01 已开发未完全验证  
执行单元：运营数据管理 agent 团队  
事实来源：`项目当前进度报告-20260711.md`、`POS收银台开发日志.md`、`app/sql/init.sql`、`app/js/charts.js`、`app/js/ui.js`、`server.js`

## 一、P0 总目标

把当前系统从“能录入、能看基础收入图表”推进到“能支撑日常经营对账与分析”的最低闭环。

本轮 P0 只解决四件事：

1. 统一经营收入统计口径。
2. 补齐退款、作废、日结报表。
3. 打通文创销售自动扣减库存。
4. 建立采购入库与库存流水。

## 二、已确认事实

- 当前版本本地 `VERSION` 为 `1.3.3`。
- 现有核心收入来源分布在 `revenue`、`gallery_sales`、`space_usage_with_payments`。
- 空间收入已重构为 `space_payments` 子表，报表中多处按 `paymentDate` 聚合。
- `creative_products` 已有 `cost_price`、`retail_price`、`stock` 字段。
- POS 文创销售写入 `revenue.retail_items` 与 `revenue.retail_amount`，但进度报告明确写明“文创扣减”仍未完成。
- 退款作废、采购入库、日结报表仍是后续 P0。
- 当前工作区已有多处运行时代码文件修改，P0 开发前必须先核对这些修改来源，避免覆盖用户或其他任务的改动。

## 三、P0 拆分

### P0-01 统一收入事实口径

- 优先级：P0
- 状态：待启动
- 服务目标：让首页、数据报表、日结报表使用同一套收入聚合口径。
- 要做：
  - 设计统一口径：`date`、`source`、`category`、`amount`、`net_amount`、`payment_method`、`project_name`、`record_id`。
  - 新增数据库视图或后端只读统计接口，用于聚合 `revenue`、`gallery_sales`、`space_payments`。
  - 让新增日结报表优先读取统一口径。
- 不做：
  - 不迁移历史业务数据。
  - 不删除现有 `revenue.venue_amount` 等兼容字段。
- 交付物：
  - SQL 视图或后端统计接口。
  - 口径说明文档。
  - 至少 3 组手工核对样例：POS 收入、画廊净收入、空间到款。
- 验收标准：
  - 同一日期在收入总览、日结报表、导出数据中的合计一致。
  - 空间收入只按实际到款日计入，不按项目开始日重复计入。

### P0-02 退款、作废、日结报表

- 优先级：P0
- 状态：待启动
- 服务目标：闭馆后能完成当天经营对账，区分真实收入、作废、退款和差异。
- 要做：
  - 给 POS 收入和画廊销售补状态口径：正常、作废、已退款、部分退款。
  - 建立退款/作废记录，保留原始交易，不物理删除作为经营调整手段。
  - 新增日结报表：收入分项、支付方式、退款作废、空间到款、画廊净收入、现金/账户差异、经手人、备注。
- 不做：
  - 不接入外部支付平台自动对账。
  - 不做财务审计级凭证归档。
- 交付物：
  - 日结页面或报表模块。
  - 退款/作废 UI 与数据字段。
  - 日结导出 CSV。
- 验收标准：
  - 当天正常收入、退款、作废分别可见。
  - 删除按钮不再承担经营退款/作废语义。
  - 日结合计能和当天收入事实口径对齐。
- 需要馆长决定：
  - 退款是否允许 editor 操作，还是仅 admin 操作。
  - 作废是否允许修改历史日期记录。

### P0-03 文创销售自动扣减库存

- 优先级：P0
- 状态：待启动
- 服务目标：文创 POS 销售后自动减少库存，并可回滚。
- 要做：
  - POS 文创销售时按商品标识匹配 `creative_products`。
  - 保存销售后扣减库存。
  - 编辑、作废、退款时按差额回滚或调整库存。
  - 库存不足时给出硬阻止或二次确认。
- 不做：
  - 不做复杂批次成本法。
  - 不做供应商结算。
- 交付物：
  - 自动扣减逻辑。
  - 库存不足提示。
  - 操作日志记录库存变化。
- 验收标准：
  - 售出 1 件，库存减少 1。
  - 作废/退款后库存恢复。
  - 编辑数量时库存按差额变化。
- 需要馆长决定：
  - 库存不足时是禁止销售，还是允许负库存并标红。

### P0-04 采购入库与库存流水

- 优先级：P0
- 状态：待启动
- 服务目标：库存数字有来源，能区分采购入库、销售出库、盘点调整。
- 要做：
  - 新增库存流水表：采购入库、销售出库、退款入库、盘点调整、报损。
  - 文创产品页增加入库入口。
  - 库存数量由流水驱动或由流水同步更新。
- 不做：
  - 不做完整进销存财务模块。
  - 不做供应商账期管理。
- 交付物：
  - `inventory_movements` 或等价表。
  - 入库 UI。
  - 商品库存流水明细。
- 验收标准：
  - 每次库存变化都有流水。
  - 入库增加库存，销售减少库存，退款/作废按规则回滚。
  - 可导出库存流水。

## 四、建议实施顺序

1. 先做 P0-01：统一收入事实口径。  
   原因：否则日结、首页、报表可能继续各算各的。

2. 再做 P0-02：退款、作废、日结报表。  
   原因：这是现金与经营分析可信度的核心。

3. 再做 P0-03：文创自动扣减库存。  
   原因：先有交易状态，才好处理退款/作废回滚。

4. 最后做 P0-04：采购入库与库存流水。  
   原因：它会扩大数据模型，但可以复用 P0-03 的库存变动规则。

## 五、开发前红线

- 涉及生产数据库结构变更前，必须先备份或导出现有受影响表。
- 涉及生产部署、权限、退款、作废、清理数据，必须经馆长或授权人确认。
- 不用物理删除代表退款/作废。
- 不覆盖当前工作区已有未确认修改。

  - `server.js` 的 `tableMap`
