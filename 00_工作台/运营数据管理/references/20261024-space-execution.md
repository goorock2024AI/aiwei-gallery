# SPACE-20261024 场地收款与执行口径

状态：本地验证通过，待授权发布。候选版本：2.0.0-rc.25。

## 已确认目标与范围

馆长已确认：日结核对实际到账，经营日报、周报、月报评价实际执行。一个订单可关联多笔收款和多个使用日期；执行确认不生成新收款。目标是避免预付款抬高收款日经营表现、执行日收入遗漏和重复录入。

本次为 L3 数据库及财务口径调整。现有开发工作区存在此前未提交工作，本次在其基础上局部修改；不把整个工作区当作发布候选，不自动提交或推送共享发布分支。

## 数据与操作

- `space_usage`：保留合同总额、客户、项目与起止范围。
- `space_payments`：继续以实际到账日记收款；退款另记负数，保留原收款。
- 新增 `space_execution_lines`：每个使用日的金额及 planned/confirmed/voided 状态。连续使用按天分摊到分，余分从首日依次分配；也可按合同逐场输入。
- 新增 `space_payment_refunds`：原收款、实际退款记录、操作者、原因关联。仅管理员可登记，累计退款不能超过原收款，退款日期不能早于到账日。
- 确认执行仅改变使用明细，不生成到账流水；不能提前确认未来日期。重复或并发确认只生效一次。
- 新增安排、确认、作废与退款均在同一事务写服务端审计。修改合同需满足已分配金额和已收款约束。
- 改期先带原因作废原明细，再安排新日期；已执行明细仅管理员可作废，撤销归属原使用日。取消订单前先处理待执行明细，已执行事实保留。
- 场地现金收款与现金退款在同一事务生成柜台现金流水。不补写历史现金账。
- 原通用 REST 场地写入关闭，避免绕过合同、执行及审计约束；已有正式场地登记与项目清单收款继续走专用接口。

## 统一报表口径

`revenue_facts` 保留到账口径，日结仍从该来源取数，名称改为“系统净收款”。

迁移首次保存已安装的 `business_revenue_facts_v2` 定义为 `business_cash_revenue_facts_v2`，保留既有分类和成本等补丁。再让原经营事实视图的场地部分只输出已确认使用明细。非场地事实逐行不变；已有利润、经营概览及分析依赖保持关联。

日报、周报、月报资料包增加 `spaceAccounting`：本期实际收款、本期已执行收入、期末已收未执行、期末已执行未收、未分配合同金额、到期未确认使用明细、旧口径待核对款项。每笔订单分别计算正余额后汇总，不能跨订单相抵；发生额按业务期间汇总，余额按截止日计算。

新资料包 schemaVersion=3，metricVersion=`operations-report-space-execution-20261024`。这是经营管理口径，不代替正式财务账务确认。

## 历史兼容和限制

- 不改写原收入、收款、日结或已归档报告，不按旧“已完成”状态自动生成执行事实。
- POS 的 `venue_amount` 没有履约证据，保留在日结，在新经营口径中排除并列出待核对金额。订单合同未分配、到期未确认也分别提示。
- 历史 POS 场地款与合同的关联需要后续人工核对和专门的数据迁移；不要重新录一笔收款来补执行信息，也不自动按名称匹配或双记旧款。
- 新旧报告数字可能因口径不同而不可直接比较。既有正式归档保留原数字及来源；重新生成资料包时使用新口径并明确缺口。
- 使用日期目前限制在合同起止范围内；本次未重做空间预约的冲突和日历占用规则。分散使用以每日执行明细统计收入。
- 押金不应记入租金；本次未新增押金子账。

## 发布准备与验收

当前仅本地开发和隔离测试。上线需馆长确认具体候选及历史待核对处理方式。

1. 从最新 healthy 发布树提取本次明确改动，不打包开发区其他未提交事项。校验共享发布分支和实际线上 SHA。
2. 备份数据库、报告归档、当前应用 SHA 和受保护配置。记录原收款、日结、报告哈希。生产数量和金额必须由授权只读 API/服务器核对，不从旧文档推断。
3. 口径切换前暂停日报准备、发送和复核任务，保留发送账本；避免自动更正任务把切换误作业务补录。
4. 通过共享发布服务执行候选迁移 `scripts/space-execution-migrate.js`，不要手工覆盖旧服务器目录。部署入口 `scripts/deploy-report-migrate.js` 已接入。
5. 核对登录、角色、场地 GET、日结净收款不变、经营场地部分为已确认执行、旧款缺口提示、报告仍可读。生产不创建测试收款或执行记录。
6. 馆长验收口径与待核对清单后恢复既有日报任务；旧归档不重写，不临时群发测试消息。

## 回退

先暂停自动日报发送与复核，保留账本。`sql/20261024_space_execution_rollback.sql` 将经营视图恢复为原收款定义，移除辅助现金视图，保留两张新表、原收款、退款负数记录和全部审计。随后恢复上一 healthy 应用，协调共享发布服务防止再次覆盖。

回退后原收款口径会重新进入经营报表；不能整库还原来撤销迁移，否则会丢失上线后正常业务。退款负数记录保留，退回旧应用前应核对旧页面的展示兼容；不删除已产生的执行、退款或归档记录。
