## 手动备份

```bash
cd /opt/aiwei
bash scripts/backup-db.sh
```

完成后应看到：

- `backups/postgres/aiwei-postgres-YYYYMMDD-HHMMSS.dump`
- 同名 `.sha256`
- 同名 `.baseline.json` 和 `.baseline.json.sha256`
- 同名 `.manifest`
- `backups/logs/backup-YYYYMMDD-HHMMSS.log`

## 安装定时任务

云端定时任务：

```bash
cd /opt/aiwei
bash scripts/install-backup-cron.sh
crontab -l | grep AIWEI_DB_BACKUP
```

如需调整时间：

```bash
AIWEI_BACKUP_CRON_SCHEDULE="17 3 * * *" bash scripts/install-backup-cron.sh
```

本地 Windows 定时任务：

```powershell
PowerShell -ExecutionPolicy Bypass -File "00_工作台\运营数据管理\scripts\install-local-backup-task.ps1"
schtasks /Query /TN AiweiLocalDbBackup
```

本地任务会先触发云端 `backup-db.sh` 生成最新备份，再把 `.dump`、`.manifest`、`.baseline.json` 拉到本机，并分别核对远端 dump 与基线 SHA。本地只保留最近 10 天。

## 只读校验

云端：

```bash
cd /opt/aiwei/backups/postgres
ls -lh
sha256sum -c <backup-file>.dump.sha256
sha256sum -c <backup-file>.dump.baseline.json.sha256
cd /opt/aiwei
docker compose exec -T db pg_restore --list < backups/postgres/<backup-file>.dump >/dev/null
```

本地：

```powershell
PowerShell -ExecutionPolicy Bypass -File "00_工作台\运营数据管理\scripts\local-backup-db.ps1"
Get-ChildItem "00_工作台\运营数据管理\local-backups\postgres"
Get-FileHash "00_工作台\运营数据管理\local-backups\postgres\<backup-file>.dump" -Algorithm SHA256
```

## 恢复演练

生产整库恢复会覆盖备份点之后的写入，只能在单独授权、冻结写入并明确数据损失窗口后执行。日常验证必须在隔离数据库或临时容器中进行：

```bash
docker run --rm --name aiwei-restore-test -e POSTGRES_PASSWORD=test -d postgres:17-alpine
sleep 5
cat backups/postgres/<backup-file>.dump | docker exec -i aiwei-restore-test pg_restore -U postgres -d postgres --clean --if-exists
docker exec -i aiwei-restore-test psql -U postgres -tAc "select count(*) from pg_tables where schemaname='public';"
docker rm -f aiwei-restore-test
```

恢复后必须运行 `sql/m6-07-baseline.sql`，比较结构指纹、表/视图数量、核心记录数、金额汇总、最新事实日期和灰度值。M6-07 在本地 PostgreSQL 17 中对同一 260,506-byte custom dump 连续恢复两次，基线一致、恢复点后探针被清除、源库不变且临时库无残留。详见 `evidence/20260911-m6-07-production-readiness-restore.md`。
