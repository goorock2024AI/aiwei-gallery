# M5-01 运营管理页面任务拆分与冻结

- 日期：2026-09-09
- 分支：`codex/operations-v2`
- 输入：M1/M2 冻结口径、M3 核心流程、M4-10 阶段评审及现有 2.0 只读事实/治理视图
- 范围：页面任务拆分、信息架构、数据源、权限和验收边界；不读写生产数据

## 结论

M5 拆分为 M5-02 至 M5-09 八个任务包，按“入口框架→四层总览→趋势比较→治理工作台→模型对应→筛选下钻导出→韧性性能→阶段评审”执行。新建独立“美术馆运营管理”入口，复用现有数据看板的底层事实与治理视图，不复制其查询和计算逻辑。

## 页面结构

1. 期间、更新时间、数据范围和 1.0/2.0 口径上下文。
2. 净收入、销售成本、期间成本、销售毛利、经营贡献和待归类影响总览。
3. 到馆参观、现场消费、体验活动、艺术交易与合作四层经营矩阵。
4. 月度收入、成本、毛利、经营贡献及口径差异趋势。
5. 治理问题、商品、收入、成本、画廊、工坊、空间和批次状态工作台。
6. 业务层、业务类型、成本类型、能力轴与经营事实的对应说明。
7. 统一筛选、来源下钻和 UTF-8 CSV 导出。

## 权限

- admin：读取完整运营管理页面，治理写动作继续走 M4 批次审批流程。
- editor：读取完整页面，可创建、dry-run 和提交批次，不能审批、应用或撤销。
- viewer：暂不开放包含成本、利润和治理明细的新入口，继续使用现有授权的 1.0 只读报表。
- 未登录：无入口，接口返回 401。

## 完成定义

- 页面值与冻结视图金额精确对账，待归类影响和 1.0/2.0 差异始终可见。
- 筛选贯穿总览、趋势、治理和导出；明细可定位来源表、来源 ID 和明细键。
- 页面分区支持独立加载、空状态、无权限和失败状态，单区失败不清空全页。
- admin/editor/viewer/未登录权限同时通过服务端和前端验证。
- 1440px 桌面和 390px 手机可用，页面异常为 0。
- 不修改原始事实，不扩大 M4 治理写权限，不连接生产或部署。

## 主要风险

1. 总览在前端重算造成 SQL 视图与页面口径漂移。
2. viewer 意外获得成本、利润或治理敏感信息。
3. 多个 5000 行查询一次加载造成性能和失败耦合。
4. 待归类金额和 1.0/2.0 差异被隐藏，导致错误经营判断。
5. 新功能继续堆入 `ui.js`，提高维护成本。

对应措施已经冻结为：汇总视图单一口径、入口权限不扩张、服务端过滤与分区加载、固定展示数据质量影响、新页面拆分独立渲染模块。
