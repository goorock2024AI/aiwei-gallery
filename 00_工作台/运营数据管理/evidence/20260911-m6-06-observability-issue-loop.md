## 1. 运行观测面

`GET /rest/v1/runtime-observability` 仅向 admin/editor 开放，返回：

- 应用版本、启动时间、进程运行时长和服务端检查时间。
- 数据库连通性和观测查询耗时。
- 迁移清单 SHA-256、正向/回滚文件数、最新迁移以及必要表/视图的缺失清单。
- `off/admin/staff` 当前灰度状态。
- 最近 500 个 API 请求的错误、慢请求、P50、P95、最大耗时及路由聚合。
- 未复验 P0/P1 数量和 G0 阻断项。

请求窗口不记录查询参数、请求体、认证令牌或账号信息。HTTP 5xx 和超过 1000ms 默认阈值的请求同时写入服务端日志。窗口属于当前 API 进程，重启后重新计数；跨重启观察使用 `references/m6-06-trial-run-observation-template.md` 留证。

## 2. 问题闭环

新增 `trial_run_issues`、`trial_run_issue_events` 和 `trial_run_issue_register_v2`。问题记录包含级别、标题、证据、影响、负责人、截止日期、修正版本、修正说明和复验结果；事件记录动作、前后状态、会话操作者、详情和时间。

| 动作 | admin | editor | 结果 |
|---|---|---|---|
| 登记、指派、提交修正、重开 | 允许 | 允许 | 形成不可省略的事件记录 |
| 完成复验 | 允许 | 拒绝 | `fixed → verified` |

P0/P1 的 `open`、`fixing` 和 `fixed` 均阻断 G0，只有 `verified` 解除阻断。专项 P1 样本完整形成 `create → assign → fix → verify → reopen → fix → verify` 七个事件；登记人和复验人均来自服务端认证会话，客户端伪造字段无效。
