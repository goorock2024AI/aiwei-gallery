# 跨月租赁登记后的日历异常修复（rc.31）

需求OPS-SPACE-CROSS-MONTH-20261028。用户跨月登记提示Invalid string length；只读核对确认请求已保存且无重复登记。修复不更改实际客户、登记、金额或收款，不替用户重录。

## 复现与根因

针对真实_renderSpaceGantt建立可执行反馈：跨月范围的结束日数字小于开始日，原跨度为负，循环日数倒退，反复拼接字符串直至RangeError: Invalid string length。使用放大测试标题加速相同路径，修复前已得到完全相同错误，修复后正常返回。标题放大仅为隔离复现加速，不是用户字段错误。

按风险排序检查跨月日历、提交后刷新和填报字段；通用数据可复现，生产只读核对排除未保存。最小边界为月底跨至下月初。旧保存流程等待列表刷新才打开已保存详情，使前端渲染错误看起来像保存失败。

## 修复

日历每个月按可见日期裁切，跨度至少一天，循环始终前进；从前月延续到本月的记录也绘制可见部分。保存、收款、使用完成和转换在提交成功后先打开已保存详情，列表刷新单独处理；刷新异常明确提示记录已保存，避免再次新建。

仅前端及缓存标识变化，后端/数据库/财务口径不变。保留原登记，不删重、不补录、不增加收款。以现有前端静态热修runbook发布：备份当前实际Nginx绑定文件，按提交字节更新JS及入口，再由共享服务归档正式版本。旧静态脚本默认旧路径，不能直接用于共享发布绑定目录；手工核对真实挂载，JS原子替换，单文件入口保持绑定inode，入口最后更新。
