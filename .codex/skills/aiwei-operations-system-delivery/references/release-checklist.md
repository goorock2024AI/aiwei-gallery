# 运营数据系统发布检查清单

## 发布前

- 确认本次任务的业务目标、范围和不做事项。
- 查看 `git status` 与相关 `git diff`，识别用户或其他会话已有改动。
- 确认是否涉及红线事项：生产部署、数据库迁移、删除数据、退款/作废、权限变更、密钥或外部发布。
- 涉及版本升级时，同步检查 `VERSION`、`app/js/app.js`、`app/index.html` cache-bust token、根 `dist/` 镜像是否需要更新。
- 涉及前端时，本地 preview 验证核心路径。
- 涉及后端时，验证 API 请求与容器日志。
- 涉及数据库时，先确认现有表、迁移脚本、`server.js` 白名单和初始化 SQL。

## 发布中

- 前端文件按单文件上传并逐个验证 mtime。
- 后端 `server.js` 修改后必须重建 api 容器。
- `VERSION` 文件与前端版本号同步时，上传到 `/opt/aiwei/VERSION`。
- 出现 SSH `Exceeded MaxStartups` 时，停止连续重试，等待至少 30 秒后再继续。

## 发布后

- 验证 HTTP 文件大小和 cache-bust token。
- 检查 API 容器日志无语法错误或启动错误。
- 验证关键 API 端点。
- 用测试账号验证核心业务流程，并清理测试业务数据。
- 补充 POS 开发日志、工作日志、版本记录和必要的复盘。

## 不可写成已完成的情况

- 只完成代码但未验证。
- 只验证本地但未确认线上。
- 部署成功但未记录版本和回滚方式。
- 通过临时脚本修复了数据但未记录脚本风险和清理状态。
